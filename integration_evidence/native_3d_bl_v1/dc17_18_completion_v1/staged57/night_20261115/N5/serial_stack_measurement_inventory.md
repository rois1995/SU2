For M12, reuse this fixture API and make a test-only flat-channel case with `topWall=true`, preserving the unit height `G=1`, with two thickness settings such as `T=0.4` (`2T<G`) and `T=0.6` (`2T>G`). One fixture detail must be addressed in that new test-only case: `SyntheticBox` maps bottom to marker 0 and top to 3, but maps only `x=0` to reflective marker 1; `y=0` is marker 4 only when `seam=true`, and the remaining sides map to artificial marker 2 (`:169-172`). `BoxRoles()` marks markers 1 and 4 as carriers and marker 2 artificial (`:196-197`). Thus the existing two-wall case does not give all four side faces symmetry roles as D5A.3 specifies. The minimal fixture extension is a test-only side-role option in the box face-to-marker mapping that routes all vertical sides to an existing reflective/carrier marker while retaining markers 0/3 for the two BL walls. No production behavior or stop policy needs to change for that test fixture adjustment.

## Existing observations for M10/M12

- **First heights and layers by wall:** `dc12::MapLayers`, `FirstHeightOf`, and `GrowthOf` in `SU2_CFD/include/adaptation/native_bl3d/BLGrowth12.inl:67-80` expose marker-to-layer mapping and each wall’s current policy. `Growth::columns` records each column’s owning wall-layer set, stack IDs, `stopped`, `stop`, and `stopHeight` (`BLGrowth12.inl:140-150`). The existing test validates each column’s law heights (`native_first_row_dc12.inc:227-233`) and checks that top-wall columns exist (`:248-250`). For M12, report per-wall column counts and `stack.size()` distribution (largest/mean), and print each column’s existing stop text/height; do not infer a replacement stop rule.
- **Growth counters:** `JsonGrowth` reports growth outcome, layers, lifted points, transactions, layer-cell count, stop/stop-reason counts, and the overall `layers_per_column` histogram (`BLGrowth12.inl:789-797`). It does not split the histogram by wall or provide the requested `vertex_cells` delta. A test-only before/after count of `s.vertex_cells.size()` bracketing `PhaseG`, alongside `G.lifted`, supplies that measurement without changing production counters.
- **MakeRoom region data:** `dc16::RoomStats` has total calls, needy tops, summed region vertices, cells, moves, and other totals (`SU2_CFD/include/adaptation/native_bl3d/BLDeform16.inl:49-51`); `JsonRoom` serializes them (`:175-180`). `MakeRoomImpl` logs one `DC16 room ... region=<size> ...` record for a nonempty region (`:90-109`, `:172-173`), and `PhaseG` calls `MakeRoom` before growth layers when `roomStep` is true (`BLGrowth12.inl:325`, `:374`, `:414`). For the requested region count and sizes, capture the existing `DC16 room` records and report their count/sizes alongside `roomStats.calls` and summed `roomStats.region`; empty/no-free-vertex attempts increment calls but may return before a per-region record.
- **Completion/surface-preparation count:** The existing production front-end sequence is R1/R2, `dc15::CompleteFirstRow`, then `PhaseG` (`SU2_CFD/include/adaptation/CNativeBLPipeline3D.hpp:612-635`). `dc15::Completion` exposes `failing_before`, `failing_after`, `surface_edits`, `surface_work`, and related counters (`SU2_CFD/include/adaptation/native_bl3d/BLEvent15.inl:307-317`); `JsonCompletion` emits them (`:379-384`). `failing_before` is the number of faces needing completion before the pass, while `surface_edits` counts completion surface edits that changed geometry. Report both; they are different measurements. The current `NativeGrowthLayer12` test’s local `run` lambda goes directly from R2 to G and omits `CompleteFirstRow`, so a new M10/M12 case should insert this existing completion API before G if it is measuring that stage.
- **Final q/J/size diagnostics:** `dc9::Final(State&)` returns `q`, `J`, `bad_shape`, `long_edges`, `lmax`, wall/height counts, unmeasurable edges, and `complete` (`SU2_CFD/include/adaptation/native_bl3d/BLFirstRow9.inl:1183-1200`). `dc9::JsonFinal` emits `q_min`, `J_min`, edge maximum, bad-shape count, long edges by class, wall/height counts, and completion (`:1201-1215`). The public growth-layer test currently checks positive orientation, volume, wall areas, and requested law heights (`native_first_row_dc12.inc:219-233`) but does not invoke `Final`; collect it after G for M12’s requested q/J/size counts.
