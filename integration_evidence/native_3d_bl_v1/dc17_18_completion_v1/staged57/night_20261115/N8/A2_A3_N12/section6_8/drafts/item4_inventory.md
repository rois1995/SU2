# 6.8 item 4 source inventory (read-only)

## Consolidated readings and source discrepancies

1. **The named frame-loop population has exactly three production call sites.** In `Common/src/adaptation/CNativeEngine3D.cpp:5317-5353`, `frames` is iterated by `for (frame...)`; within its `participating` branch, the retained wall split uses `RefitWallSplit` at 5342-5343 for `frame==0` and `ReconstructWallSplit` at 5344-5345 for the other retained frame. The non-retained/follow-on branch calls `ReconstructSplitPatch` at 5347-5349. These are the only three call sites for these exact operators found in `Common/src/adaptation` and `Common/include/adaptation`. Their execution is conditional on `participating`, `retained_frame`, `wallSplit`, frame index, and the loop/work/growth checks; “three call sites” does not mean three runtime calls per choice. The branch also contains ordinary non-wall `ReconstructSplitPatch` uses through the same named operator call when `retained_frame` is false; the function call itself has no `wall` condition at 5346-5349.

2. **Observed “valid” has two source-level meanings; reading used:** the function arguments named `valid` in `guarded_geometry` are the primitive operator bool (the `RefitWallSplit`/`ReconstructWallSplit`/`ReconstructSplitPatch` result). The lambda returns `passed`, after the existing first-height, height, boundary, and `geometry_trial` checks (4271-4278). The receiving `candidate` therefore represents the guarded result, not merely the primitive return and not later `validate_joint`/metric acceptance (5355-5365). For a new frame row, the source-supported end-to-end observed Boolean is the returned `candidate` value; it says nothing about later metric/quality approval. The distinction should be retained in the report label/documentation.

3. **Timer scope reading used:** the text calls for one clock around the frame-loop operator call. At these sites that expression is the operator call nested as the argument to `guarded_geometry`; timing the whole expression includes the subsequent guard checks, `geometry_trial`, and transaction observation executed inside that lambda (4267-4278), not only the geometry operator body. This is still print-only; no existing timer operation is needed. The enclosing `Timer`/`CpuTimer` at 5333 times candidate reconstruction scope, so its existing seconds are wider and not a substitute for a per-frame call interval.

4. **Exception path is not the same as a guarded refusal.** The three invocations are in `try` at 5334-5351; an exception is caught at 5351 and sent to `failure.Set`, before `guarded_geometry` runs. `ObserveGuard` therefore does not record such an exception as an operator refusal (`guarded_geometry` calls it only at 4276). A frame-call counter placed around the invocation can count it, but the existing refusal rows will not describe it. The specified N9 reason/refusal reconciliation is measured evidence for that run; general `calls - valid == refusal rows` is not source-guaranteed if an exception path occurs. Keep exceptions/attempted calls distinct in any reporting or preserve this as a print-only reconciliation boundary.

5. **`ObserveGuard` classification and row scope.** `Common/include/adaptation/CNativeWallDiagnostics3D.hpp:42-59` first ignores disabled counters and wholly passing guards. Guidance-origin failures increment `guidance_guard_refusals_` and return before the operator table (46-49). Non-Guidance failures call `ObserveOperatorReason(reason)` at 50; if the primitive bool was false, they also increment the operation/reason bucket at 51-52; otherwise they increment one of preserve, height, or boundary counts (53-59). Current operation mapping has only three buckets: SplitEdge, InsertEdgeCavity, and the aggregate `other_geometry` (52, 107-116). The reason classifier (`Reason`, 231-244) reads the complete input reason. The bounded printed text table (`ObserveOperatorReason`, 173-191) stores up to 96 leading characters in 16 fixed slots; it currently compares those raw prefixes. Thus decimal-run normalization belongs only to the bounded display/table key described in 6.8; changing `Reason()` would alter a different report row. Existing `GuardRefusals()` includes guidance guard failures as well (251-256), while the reason table excludes Guidance. For the requested conservation, the correct source population is failed non-Guidance guards, including post-operator preserve/height/boundary failures, not the total including `guidance_guard`.

6. **The 6.8 normalized-prefix behavior is not current source behavior.** Current code truncates first, then exact-compares/stores those raw prefix bytes (`CNativeWallDiagnostics3D.hpp:173-190`). It does not collapse decimal runs. The bounded display representation is a 96-character prefix; tails after that prefix are already indistinguishable. Under the new order, the lookup key must additionally fold each contiguous decimal run within the stored prefix to one `#`; the full reason passed to `Reason()` remains unmodified. This reduces duplicate digit-varying buckets and can change the occupancy/`more` count without changing total observations. The source makes no guarantee that normalized distinct prefixes still fit in 16 slots; overflow remains an explicit `more` count.

7. **Attribution is not yet available per named frame operation.** The old wall refusal table stores a 3-by-7 array, where all call names besides SplitEdge/InsertEdgeCavity enter the same `other_geometry` column (`CNativeWallDiagnostics3D.hpp:107-116, 167-170, 267-278`). The three new named operations are passed as strings by the engine, but this table currently folds them together. The existing 16-slot text table is global to the worker and has counts but no operation dimension. New per-operation refusal attribution therefore does not fall out of the current printed aggregate; it requires item 4's print-only classification/fields to make the call names separately visible while reconciling to the old aggregate.

8. **N9 measurement being reconciled.** The preserved Section 6.6 run `N9/section6_6/cases/N9_66_bl_20261116T135717_78861/run.log` prints 18 `other_geometry/orientation`, 4 `interface`, 25 `incomplete_star`, and 857 `other`, totaling 904. Its reason rows are 345 for the repeated base text, 15 distinct facet/cell-number variants, and 544 in `<more>`, totaling 904. SplitEdge and InsertEdgeCavity refusal rows are zero in that run. These are counts from that N9 case, not a universal per-operation statement. The 6.8 order says to partition these observed 904 refusals among the three named calls plus residual `other_geometry`; it also states all 904 came from the three named operators after a geometry-queue choice was not approved.

9. **G3 report helper behavior.** `N9/section6_6/drafts/check_g3_identity_66.py:47-67` already parses quoted `NATIVE3D_WALL_REASON` and `NATIVE3D_WALL_REFUSAL` records with `shlex`; `wall_reason_report` sums the reason rows and optionally reconciles against `wall_operator_refusal_total` (162-188). That denominator excludes only `guidance_guard` and `unwrapped_geometry_trial`, so new operation-named refusal classes would be included without changing the exclusion rule. `evaluate` returns reason reconciliation as diagnostic output, not among the gate terms at 197-247. The current parser does not collect `NATIVE3D_WALL_FRAME` records (it collects only stage, reason, and refusal rows at 47-60); item 4's new frame rows therefore need report parsing if they are to appear in the G3 report. No existing G3 acceptance check currently consumes frame calls/valid/seconds.

10. **Existing focused test is an evidence-local standalone fixture, not a production UnitTest.** `N9/section6_6/wall_diagnostics_test.cpp` includes the diagnostics header directly (1-8). It checks existing categories/partition conservation (60-89) and the 16-slot/overflow/quote behavior (91-129). Its test data covers same 96-character prefixes with different tails, overflow, and Guidance exclusion, but not digit-run normalization or separate `RefitWallSplit`/`ReconstructWallSplit`/`ReconstructSplitPatch` rows. Search of `UnitTests/` found no `CNativeWallDiagnostics3D`/`NATIVE3D_WALL_REASON` fixture. This standalone fixture is the existing place where print-only semantics are exercised; it is currently written for raw-prefix bucketing, so its assertions do not verify the new normalized display key or frame counters.

11. **Timer/session/modelled bytes.** Current `SU2NativeTiming3D::Operation` has no `WallLaw`; `Census` is already an operation (TimerTree header 33-56, names 116-165). `CNativeTimerTree3D::Session::ReservedBytes()` returns `sizeof(Session)` (205-206), and `Session` embeds the phase × operation ledger (248-319). The engine adds this reservation to `options.caller_bytes` when it owns the timer session (`CNativeEngine3D.cpp:1351-1356`); remesher timer ownership likewise adds its reservation to `control.caller_bytes` (`CNativeRemesher3D.cpp:212`). A new timer operation would append one `Record` per phase to the ledger, changing the modeled session reservation; the current expected timer summary is `fixedstorage=4120`. The 6.8 correction explicitly routes wall-law work through existing `Operation::Census`, so no operation enum/session/caller-byte change is intended. `wall_diagnostics::Counters` is a separate automatic local in `Adapt` (`CNativeEngine3D.cpp:1357`), not a `Session` member; its 16-entry table uses fixed arrays in the header and no heap/static state. New worker-local fixed per-operation counters would not change timer-session `ReservedBytes()` or the session-derived `caller_bytes` amount, though they do occupy additional local object storage; no current source accounts for that local diagnostic object via `Session::ReservedBytes()`.

## Inventory outcome

This item is print-only at the specified new rows. The three operator call sites and existing guards are present. Current source lacks digit folding and per-named-operation refusal/frame rows. The principal read-only boundary to preserve is that `candidate` is the guarded result, call timers around the full expression include guard work, and exception throws bypass `ObserveGuard`; those scopes should remain explicit in the report. The no-new-timer-operation correction is source-compatible with the existing `Census` enum entry and preserves the 4120-byte timer-session report.
