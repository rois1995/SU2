# A3 Ownership lifetime and binding notes

Scope: source-backed lifetime map of PART1 §2.8 against the current Commit candidate (validation pending); the Ownership draft remains unapplied. This is not an ownership design or a cost-model change.

- **Canonical references:** `world` is the Adapt argument. `working` is the one canonical mesh. In the current Commit base it is stored in `context.commit.working`; the Ownership draft transfers only the optional slot to `context.ownership.working` and retargets the same original-scope `ContextValue` binding. Current `source` continues to bind `Owned&` to that same object; no `Owned` value is copied or moved between slots. `selection` is the current `context.census.selection` payload and carries the cached census/queue state. `geometry` is the resolved PlanarReference, while `geometry_authority` points to its mapped authority/cache. `surface_target` is the existing by-value callback. `phase_ownership` captures these same identities by reference.
- **Persistent ownership markers:** `ownership_evaluated` is currently a two-boundary false/false array and `quality_ownership_round` starts at zero, declared immediately before the `phase_ownership` lambda; the unapplied Ownership draft adds only optional storage for these two values and keeps activation at this point. Construction evaluation marks its flag before checkpoint/census skips; quality evaluation marks its flag and round only after its gates. Both markers persist across lambda invocations until Adapt exits.
- **Invocation temporaries:** cost arrays and `complete_stars` are allocated and consumed within one `phase_ownership` call. If migration proceeds, `pending`, `pending_initial`, `pending_directory`, `pending_selection`, outgoing cached rows, received records, and `PartitionStats` coexist with active canonical state until the final vote/observer succeeds. Only then does the code retire active directory stats, swap `working`/directory/Selection state, reset the queue/edge caches, and update counters. An early return leaves current ownership intact.
- **Construction/destruction:** `pending_selection` invokes the existing `Selection` constructor with the shared geometry/stats/heights references and is destroyed at lambda exit, releasing its staged containers. `pending_directory` is a `unique_ptr` built from the same World/geometry parameter authority and is destroyed on any pre-swap return. `Repartition` has a local timing `Envelope` whose destructor records total/other time, including release of its local graph/staging buffers.
- **Selection/geometry coupling:** `pending_selection` is constructed with the same geometry, stats, timing, tolerance, height-policy and mode references as active Selection. Cached `Selection::CachedRow` records carry cell state and edge lengths; quality migration also preserves repair state. The source comment says migration does not query geometry, recompose a target, or project CFD fields. The geometry authority’s `StructuralEstimate(...).prepared_pieces` and scope-build snapshot are instead inputs to the preceding estimate.
- **Cost and report path:** complete star sizes come from `VertexStarSizes`; weights are normalized from local/global maxima, with predicted imbalance/gain/cost and a rank-consistent collective proceed. `Repartition` fills `PartitionStats`. `NATIVE3D_PHASE_OWNERSHIP` and `ReportOwnershipMemory` are timing-gated observations, alongside existing `EngineStats` ownership accumulators; no new decision counter or ownership observer was found.
- **Capture/size/accounting:** the lambda uses `[&]`, and its helper/nested lambdas read canonical locals. Scratch uses explicit `sizeof` estimates for work vectors, Selection cached rows, IDs and rank structures. `bytes()` plus source/directory resident values form the caller baseline; migration separately accounts pending mesh, outgoing cache rows and returned records. The Adapt body’s only raw `decltype` is the checkpoint blocked-map swap; no `typeid` is used. These are accounting/lifetime dependencies, not inferred quotas.

No deterministic cost change, state merging/reset, or behavior repair is proposed here.
