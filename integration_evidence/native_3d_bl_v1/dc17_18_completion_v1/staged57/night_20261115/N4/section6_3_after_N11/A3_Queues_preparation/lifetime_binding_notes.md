# A3 Queues lifetime and binding notes

Scope: read-only map of the current A3 Census candidate (validation pending). PART1 `2.3 Queues` describes `inactive_blocked_edges`, `inactive_blocked_links`, `length_blocks_dirty`, and the queue half of `Selection`; the older PART1 line numbers are not used as current source positions.

- **Construction / lifetime interleaving:** `EngineContext context` is created after geometry resolution; `EngineControl control` and then `EngineCensus census` are context members. `result` is activated at 1567, `working` is declared at 1570, and the Selection `ContextValue` at 1571. Thus the Selection wrapper is an Adapt local even though storage is `context.census.selection`; its destructor resets that optional at the original scope exit. It dies before `working`, result/stat payload, and `EngineContext`. Census payload wrappers are interleaved with ordinary queue locals: generation window wrappers 1582–1585, retired/campaign maps 1586–1589, inactive blocked state 1590–1591, field identity 1592–1593, and later seed vectors/cursor 1626–1631.
- **Aliasing:** `Selection` is a canonical shared object between Census and Queues. It retains references to resolved `geometry`, the single `result.stats` object, and `options.wall_heights`; changing object identity would affect queue decisions, measurements, reports, and memory accounting. Its scalar mode members are copied/owned by Selection, while `coarsening`/`construction_kind` remain Control locals that `length_direction` updates together with `selection.coarsening`.
- **Direction switching:** `length_direction` is a `[&]` lambda at 3228. It swaps `selection.blocked_edges`/`blocked_links` with `inactive_blocked_edges`/`inactive_blocked_links`, updates both `coarsening` and `selection.coarsening`, writes `construction_kind`, and consults/resets `length_blocks_dirty`. These are one transition state set, not duplicate independent blocked caches.
- **Ownership and checkpoint interactions:** `phase_ownership` is `[&]` and migrates/restores Selection state; it calls `selection.SwapState(pending_selection)` at 3424, then clears the inactive blocked map/counter and both dirty flags at 3426. `capture_checkpoint` snapshots `selection.blocked_edges`; `rollback_checkpoint` swaps it back (current lines 3544 and 3589). Queue state moves with the same Selection identity and checkpoint protocol.
- **Reference captures:** Setup/loop lambdas generally use `[&]`; queue-sensitive examples include `coalesce`, `service_frontier`, `length_direction`, `phase_ownership`, `begin_length_generation`, `enter_phase`, `capture_checkpoint`, `rollback_checkpoint`, and loop `pick`/`refuse`/`plan_choices`. They close over the same `selection`, local blocked maps/flags, and Control state. The Census `measure`/`seed_next` closures also reference Selection because it is shared, not because those queue fields are owned by Census.
- **Raw `decltype`:** current source has `decltype(checkpoint.blocked)().swap(checkpoint.blocked)` in rollback (line 3529). It is a checkpoint member-type dependency, not a queue-field type alias. No raw `decltype(selection...)` was found.
- **Size/accounting:** `Selection::Bytes()` at 547–550 includes the queue and census containers in the same object, including main/surface/geometry queues, frontier/history, repair maps/queues, vertex/blocked maps and link-count estimates. `GeometryPriorityBytes()` has an explicit `sizeof(pair<const Edge,long double>)+4*sizeof(void*)` estimate at 439–441. Adapt `bytes()` includes `selection.Bytes()` plus the inactive blocked map/counter (1699–1700). Other queue-admission paths have their own `sizeof` estimates; preserve them where used. A moved queue field must not be counted twice or dropped from these formulas.
- **Accepted observations relevant here:** geometry-priority scoring is visible in `geometry_queue`/`geometry_split_priorities` and is decision state. D9, wall, and lane counters plus fixed lane-slot metadata remain their separate print-only/measurement objects in EngineSetup and the trial frame. Do not merge diagnostic observations into queue ordering or memory admission.

No `EngineQueues` type or `EngineContext::queues` member is present yet; this note describes current state only and makes no scope proposal.
