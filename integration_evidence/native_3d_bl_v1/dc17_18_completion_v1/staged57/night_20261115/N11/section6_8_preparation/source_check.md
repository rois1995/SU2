## Inventory: proposal, source path, and counter scope

1. **Current per-face score and geometry queue.** In `Common/src/adaptation/CNativeEngine3D.cpp:1037-1071`, `Selection::Add` inspects physical faces when `geometry.ExtensionComponents()` is nonempty. For each face it computes exact `SurfaceDeviation`; if the error is finite and above `tolerance`, its old contribution to each of the three face edges is `(error - tolerance)^2 * squared_edge_length`. `geometry_scores` is local to this `Add`, so contributions from multiple failing faces are accumulated by edge before storage in `row.geometry_scores` (`:1063-1071,1080-1086`). Nonfinite face error marks the row unmeasured/invalid but skips its edge contributions (`:1044-1049,1063-1066`).

2. **Queue storage and choice origin.** Positive cached scores enter `geometry_queue` only for noncoarsening edges in `construction_frontier` and not blocked at the relevant endpoint (`CNativeEngine3D.cpp:1080-1086`). The scores are removed/reinserted from row state in `Drop`, `ChangePhase`, `Touch`/reactivation and `ServiceEdge` (`:798-800,859,917-921,1161-1172`). `GeometryPriority` uses the cached score directly except in its separate priority mode (`:431-460`). `Selection::Best` takes a geometry-queue entry first and sets `Choice::geometric=true`; the length queue sets it false (`:657-672`). The engine obtains this choice at the start of a selection round (`:3479-3486`). Thus the applicable B2 arithmetic point is the per-face contribution in `Selection::Add`, before its sum is stored and later queued.

3. **B2 reading.** For each finite exact failing physical face in a surface-target `Adapt` call, use that face's binding facet as the `EstimateWallEdge` anchor and evaluate the face's three edges. Let `s_max` be the largest supported value only when all three estimates are supported. If any estimate is unsupported or `s_max == 0`, retain the old contribution for all three edges. Otherwise multiply each old per-face contribution by `(s(edge)/s_max)^2` before adding it to the accumulated edge score. This leaves exact face failure detection, edge aggregation, queue admission, priority ordering, operator selection and all validity checks intact. `surface_planning` in `Selection` is initialized from `bool(surface_target)` (`:420-421,1467-1470`); the B2 applicability test must remain local to that flag. The current `Selection::Add` also filters active surface markers by requested heights when surface planning is active (`:1040-1042`); do not broaden that existing source predicate as part of B2.

4. **Law API and “unsupported” behavior.** `Common/include/adaptation/CNativeWallGeometryLaw3D.hpp:15-32` exposes the pure wall estimate API. `CNativeWallGeometryLaw3D.cpp:15-29` makes endpoint support eligible only when marker and `Entity` match the anchor; `:32-42` evaluates the curvature/normal endpoint score; `:44-78` treats no eligible side, evaluation exceptions, or nonfinite score as unsupported; `:80-101` also returns unsupported for a missing endpoint, nonfinite chord, failed facet lookup, or either unsupported endpoint. The public threshold helper is strict `value > .75*tau` (`:103-105`). B2 uses the raw supported `value` for its relative weighting, not `EstimateSaysNeed`; that helper remains for the later B1 proposal. On unsupported estimate, B2's stated fallback is the unchanged old score, not a fabricated zero, a partial weight, or a change to the law's support policy.

## One consolidated list of contradictions and readings

1. **D 4.1 versus the specific B2 formula.** D 4.1 says “largest `s(e)` first” for the proposed S1 design (`ADAPTATION_ONE_ENGINE_DESIGN_V1.md:263-289`), while I B2 and the accepted implementation note prescribe multiplying each existing failing-face score by `(s(e)/s_max)^2` and aggregating (`IMPLEMENTATION_8_3_8_4.md:202-217`). These are not the same queue ordering: B2 retains the exact-error/edge-length contribution. Reading used: implement the narrower, later B2 formula in I / implementation text; do not replace geometry-queue priority with bare `s(e)` ordering.

2. **Unsupported estimate semantics.** I B2 says one unsupported estimate triggers factor one for all three edges; the current law can mark an estimate unsupported because any eligible side at either endpoint fails evaluation, not only because no side exists. Reading used: rely on `WallEdgeEstimate.supported` as returned by the unchanged law and use the stated all-three fallback. No change to unsupported-side semantics or to `EstimateSaysNeed`.

3. **Weighted/fallback face counters lack a stated population boundary.** I B2 names counters but does not spell out whether nonfinite exact surface-error faces count. Current source skips those faces before forming edge scores (`CNativeEngine3D.cpp:1044-1049,1063-1066`). Reading used for the print-only counts: count a face as weighted or fallback only when it has a finite, exact failing error and thus contributes to the geometry-score map; a nonfinite unmeasured face contributes to neither. Report the source behavior; do not add a result gate or new handling.

4. **Acceptance attribution is absent from the aggregate.** `EngineStats::accepted` covers region publication, normal selection publication and repair batch commits (`CNativeEngine3D.cpp:2654-2658,6043-6054,6314-6319`). It does not itself identify queue origin. Reading used: report queue-specific accepted split counts from the actual selected choice's successful split publication, while preserving the existing total. Do not infer queue acceptance as guidance success minus validation failures.

5. **New reporting rows are additions, not grounds to weaken old checks.** N11 adds weighted/fallback face counts and queue-origin accepted split counts; existing diagnostics already classify guidance origin. These print-only rows do not relax the N11/N10 physical validity requirements or any unchanged-result gate. The old `geometry_bad + size_bad < 7,984` purpose rule is explicitly withdrawn by Night 6.6 (`NIGHT_WORK_ORDER.md:364-369`).

6. **No proof-of-termination claim follows from the score change.** D 4.1 describes an estimate and a longest-edge convergence argument, but B2's retained score weighting is not a proof that all failing faces will pass in finite work. Use the explicit empirical purpose gate only; do not claim a geometric theorem, change limits, or add retries.

7. **D 5.9 / 5.10 are not N11 authorization.** D's local-copy/pass merge and contact-proof proposal (5.9, `:600-721`) and the collective patch-operator restrictions (5.10, `:723-733`) concern future S1/8.5 work. N11 changes only the existing global geometry-queue weighting. No local wall-state mutation, contact-proof bypass, migration, patch-operator dispatch or 8.5 implementation is part of B2.
